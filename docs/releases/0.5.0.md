# OpenCrawl core v0.5.0

Self-hosted Better Auth now uses the PostgreSQL application database. Accounts,
password hashes, memberships, invitations, browser sessions, signing keys and
CLI/MCP OAuth grants live alongside application state in the database configured
by `OPENCRAWL_DATABASE_URL`, in a namespace-bound authentication schema.

## Breaking change: SQLite authentication is no longer supported

The runtime no longer opens `identity.sqlite` and has no SQLite authentication
fallback. PostgreSQL is required even when using the optional SQLite FTS5 search
index. `OPENCRAWL_IDENTITY_PATH` applies only to the legacy import tooling; it
cannot select the authentication backend. Cloud continues to use WorkOS.

New installations use the application PostgreSQL database provided by Compose or
Helm, or an operator-owned external database. No separate authentication database,
hosted OpenCrawl account or authentication service is required.

## Existing installations

This is a breaking release. Migrate an existing SQLite installation separately
before starting the new runtime. Ask your agent to inspect the deployment, take
a matched recovery backup and follow the
[application-state upgrade guide](https://github.com/getopencrawl/opencrawl-core/blob/v0.5.0/docs/app-state-migration.md).
The existing offline import tools remain available; this release adds no new
migration or compatibility layer.

Preserve organization and user IDs, password hashes, memberships, signing keys,
OAuth records, private configuration and source data. Do not initialize an empty
replacement account store over an existing installation. Stop old writers before
cutover and verify sign-in, CLI/MCP authorization and retained data afterward.

Rollback requires the previous runtime and the complete matched recovery point;
do not run old binaries against the new storage. See the
[restore procedure](https://github.com/getopencrawl/opencrawl-core/blob/v0.5.0/docs/upgrades.md#restore-a-matched-recovery-point).

## Versions and artifacts

Core **0.5.0** pins the independently published **CLI 0.4.94**. The PostgreSQL
runtime switch previously landed on main in
[PR #312](https://github.com/getopencrawl/opencrawl-core/pull/312); this minor
release makes the break explicit relative to stable core 0.4.1.

Use the tagged repository for the complete self-host distribution. The attached
runtime archive matches the published core package; `SHA256SUMS.txt` records its
checksum. Kubernetes users can use the independently versioned **Helm 0.2.0**
self-host kit with pinned public amd64/arm64 images.
