# OpenCrawl core v0.4.1

This release adds durable event identities for large session histories, coordinated self-host upgrades, and a clearer conversation view for captured sessions and the message board. Core remains a pre-1.0 self-host preview.

## What's new

- **Large histories and documents.** PostgreSQL stores immutable event fingerprints, replacing growing object-store ledgers. Idempotent retries and conflicting-event rejection remain enforced. Search batches adapt to provider request limits; larger individual documents no longer face the previous application-level size cutoff.
- **Recoverable upgrades.** Startup preserves the old runtime images before building replacements, creates a matched recovery point, migrates storage, and resumes interrupted upgrades. Existing accounts, credentials, organization IDs and data are retained.
- **Conversation views.** Captured sessions and board channels have conversation layouts, human participants, shared-session filters and message permalinks. Board posts no longer have the earlier application-level length caps.
- **Capture and indexing.** Cursor and Google Antigravity support, durable indexing handoff, upload batching, longer renewable device grants and reuse of self-host browser sessions during CLI onboarding.
- **Google Drive indexing.** Docs, Sheets, Slides, PDFs and text files can be indexed when content is accessible to every active workspace member. Verified member email addresses and provider permissions are required; see [setup and limits](https://github.com/getopencrawl/opencrawl-core/blob/v0.4.1/docs/google-drive.md).
- **Usage resilience.** A failed measurement no longer prevents the rest of the Usage page from loading.
- **Complete runtime archive.** The npm package now includes the compiled self-host console. Publication checks reject archives that omit its JavaScript or CSS.

## Upgrading an existing self-host installation

**This release migrates event identities to PostgreSQL. Read the [upgrade guide](https://github.com/getopencrawl/opencrawl-core/blob/v0.4.1/docs/upgrades.md) before starting.** Keep the original checkout, private configuration, Docker project and startup options. Update that checkout to `v0.4.1`, then inspect the plan:

```sh
./deploy/upgrade.sh --installation deploy --check
```

Run your usual `./deploy/up.sh` command with the same options to perform the coordinated upgrade. Installations created with `./dev/up` should use `--installation dev` for the check and their usual `./dev/up` command to upgrade. Allow disk space for saved images and the full recovery point. Keep backups private: they contain credentials and user data.

Compose provisions the application database on its existing PostgreSQL server. Separately operated receivers and workers must configure `OPENCRAWL_DATABASE_URL`, stop old writers and follow the [event identity migration](https://github.com/getopencrawl/opencrawl-core/blob/v0.4.1/docs/event-identity-migration.md). Search backend changes are separate migrations.

An unfinished earlier upgrade must resume at its recorded target. Do not delete its journal or assume this release repairs a missing old image. Custom storage overlays and the removed fixed-identity capture-only distribution require a reviewed migration.

## Rollback

**Do not start v0.3.10 against migrated storage.** Returning to JSON-era code requires the entire matched pre-upgrade recovery point, including old images and all stores. Preserve data written since that backup before restoring. The [restore procedure](https://github.com/getopencrawl/opencrawl-core/blob/v0.4.1/docs/upgrades.md#restore-a-matched-recovery-point) requires stopped writers and empty destination volumes; it does not delete newer data for you. External Airbyte installations need their own backup procedure.

## Versions and artifacts

Core **0.4.1** pins the already-published **CLI 0.4.73** for its setup script. The CLI remains independently versioned and released. In CLI 0.4.73, Cursor hook uploads can exceed their deadline on large existing capture profiles; [the independent CLI fix](https://github.com/getopencrawl/opencrawl-core/pull/301) tracks that limitation.

Use the tagged repository for the complete self-host distribution. The attached `.tgz` is the published core runtime package; `SHA256SUMS.txt` records its checksum.
